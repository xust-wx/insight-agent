## 1. 背景

业务人员（运营、品类、管理层）经常提出“是什么 + 为什么”类问题，例如“2018 年 Q2 圣保罗州 GMV 为什么环比下降？”。现状：

- **BI 看板**只能回答预设指标的“是什么”，不能按需下钻回答“为什么”。
- **人工分析**依赖数据分析师写 SQL + Python，排期 1~3 天。
- **单轮 Text-to-SQL** 无法处理多表口径、易产生字段 / 数字幻觉，也不会做归因。

| 场景 ID | 场景 | 示例问题 | 优先级 |
| :-- | :-- | :-- | :-- |
| SC-1 | 指标查询 | “2018 年 3 月各州 GMV Top 10？” | P0 |

| SC-4 | 因素分解 | “GMV 变化中，订单量与客单价各贡献多少？” | P1 |
| SC-5 | 体验 / 履约分析 | “延迟交付是否导致差评？哪些卖家州最严重？” | P1 |
| SC-6 | 留存 / 复购 | “按首购月份的复购率 cohort？” | P2 |

## 3. 功能需求

| ID | 需求 | 说明 |
| :-- | :-- | :-- |
| FR-1 | 口径理解 | 业务词 → 指标字典 → 表 / 字段 / 计算公式；口径歧义时**主动澄清** |
| FR-2 | 分析规划 | 复杂问题先输出分析计划（步骤 + 维度），再执行 |
| FR-3 | 只读取数 | 生成 SQL，经安全校验后在只读账号下执行 |
| FR-4 | 沙箱计算 | 所有统计计算、作图在隔离沙箱中由代码完成，**禁止模型心算** |
| FR-5 | 定量归因 | 维度贡献度拆解、乘法因素分解、异常点检测 |
| FR-6 | 自修复 | SQL / 代码报错、空结果时自动修正，超过上限熔断 |
| FR-7 | 人机协同 | 高成本查询、口径歧义时中断等待用户确认 |
| FR-8 | 流式输出 | 推理步骤、SQL、图表、结论实时推送 |
| FR-9 | 可溯源报告 | 报告中每个数字可追溯到具体 SQL / 代码执行结果 |
| FR-10 | 记忆 | 记住用户确认过的口径与偏好，跨会话复用 |

## 4. 非功能需求与 KPI（S4 验收依据）

| 指标 | 目标值 |
| :-- | :-- |
| SQL 可执行率 | ≥ 95% |
| 数值精确匹配率（Golden Set） | ≥ 85% |
| 归因题逻辑完整性（LLM Judge，1-5 分） | ≥ 4.0 |
| 数字幻觉率（报告数字无执行溯源） | ≤ 2% |
| 安全攻击拦截率 | 100% |
| 单题平均耗时 / P95 | ≤ 30s / ≤ 60s |
| 单题平均 Token 成本 | 记录并较 Baseline 下降 |

## 5. 安全红线
1. 数据库账号**只读**；SQL 经 AST 校验，仅允许单条 `SELECT` / `WITH`，强制 `LIMIT`。
2. 模型生成的代码**只在断网、限资源的 Docker 沙箱**内执行，宿主机不 `exec`。
3. API Key 仅存于本地 `.env`，不入库、不进日志。
4. 用户输入视为不可信：防 Prompt 注入（拒绝改写系统指令、越权查询）。
