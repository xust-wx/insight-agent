## 1. 背景与方法论边界

业务人员（运营、品类、管理层）经常提出“是什么 + 变化拆解”类问题。传统方案存在明显断层：
- **BI 看板**：只能展示固定聚合指标，无法按需多步下钻。
- **人工取数分析**：排期长，重复口径对齐成本高。
- **单轮 Text-to-SQL**：面对一单多品、一单多付、评价重复、空值品类等真实脏数据时极易算错，且不具备多维拆解能力。

> **重要边界声明（贡献拆解 ≠ 因果推断）**：
> Olist 公开数据集仅包含交易、商品、履约与评价结果数据，**不包含曝光流量、广告投放、促销日历、竞品价格等外部干预变量**。因此，本项目中的“归因”在产品与统计意义上严格界定为**定量贡献度拆解（Contribution Decomposition）与相关性验证**（回答“变化主要由哪些地区/品类/价格或销量因素构成”），**不做未经数据支撑的因果断言**。Agent 生成的所有拆解报告必须附带数据边界说明。

## 3. 功能需求

| ID | 需求名称 | 详细说明 |
| :-- | :-- | :-- |
| FR-1 | 口径对齐与歧义澄清 | 基于 `03_metrics_glossary.yaml` 映射业务术语、过滤条件与维度兼容性；遇到口径歧义（如“成交额含不含运费”“算全部有效单还是仅已送达单”）或查询落入稀疏月份（2016 年、2018-09 及以后）时，**主动触发 HITL 澄清**（也可在非交互评测模式下按默认口径执行并声明假设）。 |
| FR-2 | 显式分析规划 | 对多步问题先生成结构化分析计划（目标指标、对比基准期、拆解维度、统计方法），再逐步执行。 |
| FR-3 | 安全只读取数 | SQL 经 `sqlglot` 全语法树安全校验后，在 PostgreSQL 只读事务中执行；自动识别结果集是否截断（`truncated`）。 |
| FR-4 | 沙箱确定性计算 | 同比环比、贡献度占比、LMDI 分解、PVM 结构效应、显著性检验及可视化图表，全部在无网隔离沙箱中调用预置分析库完成，**严禁大模型心算数字**。 |
| FR-5 | 多维定量拆解 | 支持加法维度拆解（ΔY = Σ ΔYᵢ）、两因素对数分解（GMV = 订单量 × 客单价）及价格-销量-结构（PVM）效应拆解（防范辛普森悖论）。 |
| FR-6 | 错误自修复与熔断 | SQL 报错、结果为空、维度不兼容或 Python 报错时，基于结构化错误提示自动修正；单节点最多重试 3 次，全局最多 12 步，超限输出已完成证据与失败说明。 |
| FR-7 | 人机协同（HITL） | 在口径歧义确认、稀疏时间区间确认、高代价 SQL 拦截三类条件下支持中断（`interrupt`）与用户确认后恢复（`resume`）。 |
| FR-8 | 流式透明输出 | 通过 SSE 实时推送当前节点、生成的 SQL、沙箱执行摘要、图表产物与最终报告。 |
| FR-9 | 数字溯源与免责声明 | 报告中的核心数值必须可在当次 SQL 或沙箱标准输出中溯源；拆解类报告末尾自动附上“贡献拆解非因果推断”的数据边界说明。 |
| FR-10 | 确认态口径记忆 | 仅在用户通过 HITL **明确确认**某一口径偏好后写入持久化记忆，支持后续会话读取、覆盖与清空。 |

## 4. 评测基线定义与量化验收指标（S4 验收依据）

### 4.1 评测集与标准答案准则
- **Golden Dataset 规模**：40~50 道分层题目（Tier-1 单指标/多表查询 15 题、Tier-2 趋势与复合口径 10 题、Tier-3 多维贡献拆解 10 题、Tier-4 边界/歧义/安全攻击 10 题）。
- **标准答案来源**：**100% 由人工编写 SQL 与 Python 脚本在真实库上跑出并交叉核对**，严禁使用大模型生成标准答案。数值比对容差：金额/计数允许 `±0.01`，百分比/贡献度允许 `±0.5 个百分点`。

### 4.2 对照基线（`v0-baseline`）精确定义
- 单次 LLM 调用，直接注入 9 张表原始 DDL（不含口径字典与已知陷阱），生成 1 条 SQL 执行并由 LLM 直接根据查询结果文本总结回答；无 AST 修复循环、无 Python 沙箱计算、无预置拆解库。

### 4.3 验收 KPI 表

| 指标类别 | 指标名称 | 精确测量方法 | 目标值（`v2` 最终版） |
| :-- | :-- | :-- | :-- |
| **准确性** | SQL 最终可执行率 | 评测集中最终采纳的 SQL 在只读库执行不报错的比例 | **≥ 95%**（且高于 `v0-baseline`） |
| **准确性** | 核心数值精确匹配率 | 最终回答中的目标指标值落入人工标准答案容差范围内的题目占比 | **Tier-1/2 ≥ 88%，整体 ≥ 80%**（较 `v0-baseline` 提升 ≥ 20 个百分点） |
| **拆解质量** | 贡献拆解完整度 | Tier-3 题目命中人工标注 Top-3 贡献项且方向一致的比例 + LLM Judge 逻辑评分（1~5 分） | 关键贡献项命中率 **≥ 85%**，Judge 均分 **≥ 4.0** |
| **忠实度** | 无溯源数字幻觉率 | 正则抽取报告中所有业务数值（排除日期/序号），在当次 SQL 返回结果或沙箱 `stdout` JSON 中找不到匹配值（含四舍五入容差）的数值占比 | **≤ 2%** |
| **安全性** | 安全攻击拦截率 | `docs/security_cases.md` 中 SQL 注入、可写 CTE、系统表探测、Prompt 越权、沙箱逃逸用例被拦截的比例 | **100%** |
| **性能** | 分档响应延迟 | 本地数据库 + 正常 API 速率下端到端耗时（不含人工 HITL 等待时间） | **Tier-1 查询**：P50 ≤ 12s，P95 ≤ 20s<br>**Tier-2/3 拆解**：P50 ≤ 45s，P95 ≤ 75s |
| **成本** | 单题 Token 预算与性价比 | 记录每题输入/输出 Token，输出 `v0 → v1 → v2` 的 **成本-准确率权衡表** | Tier-1 平均 ≤ 8K tokens；Tier-3 平均 ≤ 28K tokens；单题硬上限 60K tokens |

## 5. 安全与合规红线
1. **多层数据库只读隔离**：数据库层 `default_transaction_read_only = on` + 最小 `SELECT` 授权 + `statement_timeout = 15s`；应用层 `sqlglot` 全 AST 遍历拦截任何 DML/DDL/可写 CTE/危险系统函数/多语句。
2. **加固无网沙箱**：模型生成代码仅在 `--network none`、`--cap-drop ALL`、`--pids-limit`、非 root 用户的受限 Docker 沙箱中执行，宿主机严禁 `exec`/`eval`。
3. **密钥与隐私保护**：API Key 仅存 `.env`；免费层 Gemini API 存在平台侧数据改进条款，因此**严禁接入任何真实企业私密数据**，仅使用公开 Olist 数据集。
4. **不可信输入隔离**：用户输入通过结构化字段传递，工具执行层实施确定性校验，不依赖 Prompt 劝导模型“自觉守规矩”。

## 6. 非目标（本期不做）
- 任何写库 / 数据修改能力、因果推断建模（如双重差分 DID / 倾向得分匹配，因数据无干预变量）、多租户行级权限控制、高可用集群部署、模型微调。
